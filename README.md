# 精确分数运算（从 0 实现）

起始环境只有本说明、`samples/**` 与 `.gitignore`：分数的表示与规范化、四则运算与整数次幂、取整与取余、
运算链解析、命令行、一页自包含 HTML 报告都从零写；入口是仓库根目录的 `fractionkeep.py`。
Python 3.13 标准库，不引第三方、不加构建、不联网，测试写在 unittest 里。

## 一、范围

做：解析 `p/q` 形式的精确分数与运算链 → 逐步执行加、减、乘、除、整数次幂、取整与取余 → 每一步都先规范化
再继续 → 逐行核对 `samples/expected/**` → 生成 `var/fractions.html`（数据与样式内联、无脚本、双击即开、
不引外链）。

不做：浮点与小数近似（全程不出现二进制浮点）；根式与对数；代数符号与多项式；带分数、百分数与科学计数法；
数据库、网络、多进程多线程；除 `var/` 与指定输出文件外不落盘，`samples/**` 只读。

## 二、口径与公式

值一律表示为整数对 `(p, q)`，q 为正。**规范化**：g = gcd(|p|, q) 约到最简，p = 0 时记作 `0/1`；
规范化后是唯一表示，两个值相等当且仅当 (p, q) 相同。输入允许 `2/4`、`-0/7` 这类写法，先规范化再用；
分母 ≤ 0 是输入错误。

位数：`L(n)` 是 |n| 的十进制位数，L(0) = 1；一对数的位数 = L(分子) + L(分母)。每步记**约分前位数 rd**
（(P, Q) 的位数）与**约分后位数 nd**（规范化结果的位数）。未约分对的分母恒为正：算出负分母时把符号挪到分子。

设当前值 x = p/q、操作数 m = s/t（都已规范化）：

| 记号 | 含义 | 未约分对 (P, Q) | 规范化结果 |
| --- | --- | --- | --- |
| `+` `-` | x ± m | (p·t ± s·q, q·t) | 规范化 (P, Q) |
| `*` | x · m | (p·s, q·t) | 规范化 (P, Q) |
| `/` | x ÷ m（s ≠ 0） | (p·t, q·s) | 规范化 (P, Q) |
| `^k` | x 的 k 次幂，\|k\| ≤ 1000 | k ≥ 0: (p^k, q^k)；k < 0 且 p ≠ 0: (q^−k, p^−k) | 规范化 (P, Q) |
| `//` | x 除以 m 的整数商（s ≠ 0） | (p·t, q·s) | (⌊p·t ÷ (q·s)⌋, 1) |
| `%` | x 除以 m 的余数（s ≠ 0） | (p·t − s·q·k₀, q·t)，k₀ = ⌊p·t ÷ (q·s)⌋ | 规范化 (P, Q) |

约定：`x^0 = 1`（含 `0^0`）；`0` 的负数次幂、除数为 `0`、分母 ≤ 0、|k| > 1000 都是输入错误。
`//` 向下取整（负值也向 −∞ 取），`%` 的余数满足 0 ≤ r/|m| < 1，符号与除数一致，r = 0 当且仅当 m 整除 x。

比较：三路比较 = 交叉相乘 p·t 与 s·q 的大小（q、t > 0），不许用浮点；排序 = 按数值升序、同值只留一条
（规范化表示唯一），负数排在零与正数前面。

## 三、数据结构与流程

一条链 = 一行 `start <值>` 加若干步 `<操作> <参数>`，步号从 1 开始。流水线：解析 → 逐步运算（每步先按
上表写出未约分对，规范化后才进入下一步）→ 汇总（位数峰值、数值极值）→ 逐行核对期望 → 渲染报告。
每个样例只有「通过」与「输入错误」两种终态；中间状态是当前值 (p, q) 与每步记录（步号、操作、操作数、
P、Q、rd、nd）。

## 四、输入输出与文件格式

所有文件 UTF-8 无 BOM、`\n` 换行、末行有换行；数字十进制。

### 4.1 链文件 `samples/chains/*.txt`

`#` 开头与空行忽略；第一条有效行必须是 `start <值>`，其后每行是 `<操作> <操作数>`：操作取
`+ - * / // % ^`，`^` 的操作数是整数，其余是 `p` 或 `p/q` 形式的值。链名 = 文件名去扩展名，步数至少 1。

### 4.2 命令

```
python3 fractionkeep.py run    <链文件>
python3 fractionkeep.py cmp    <值> <值>
python3 fractionkeep.py sort   <值> [<值> …]
python3 fractionkeep.py report [<样例根目录>=samples] [<输出文件>=var/fractions.html]
```

`run` 逐行打印，第一行是汇总，其后每步一行：

```
chain <名> start=<p/q> steps=<n> final=<p/q> peak=<k> raw_peak=<k> budget=64
step <i> <操作> <操作数> raw=<P/Q> rd=<r> norm=<p/q> nd=<d>
```

peak 是全部规范化结果（含 start）位数的最大值，raw_peak 是各步 rd 的最大值，`<操作数>` 按规范化后的写法打印。
`cmp` → 一行 `cmp=-1`、`cmp=0` 或 `cmp=1`；`sort` → 去重后的升序列表，一行一个。

### 4.3 期望脚本 `samples/expected/<名>.txt`

`#` 开头是注释；`? ` 开头的行是本工具的参数（等价于 `python3 fractionkeep.py <参数>`，路径相对仓库根），
紧随其后的行是上一条命令的期望 stdout，连末尾换行逐字节比对。

### 4.4 报告

`report` 先执行 `samples/expected/*.txt`（按文件名升序）里的每条 `? ` 命令并逐行比对：全部一致时 stdout
一行 `ok=<命令条数>` 并写 HTML，有不符时每处一行 `mismatch=<参数>`、退出码 1、不写 HTML。

HTML 每条链一节：链名、步数、起始值与最终值、规范化位数峰值与预算（64）的对比结论、约分前位数峰值，
以及全部规范化结果（含起始值）的最小值与最大值；逐步表格一步一行，列出步号、操作、未约分对、rd、
规范化结果、nd（上万步的链也要完整）。页面上的数字一律由引擎先算好再写进去，不许在页面里重算。

## 五、性能与验收口径

测试机 Windows + Python 3.13、单进程单线程。

1. 逐条核对：`report` 必须给出 `ok=16`，报告里没有不符项。
2. 不变量：输出里的每个分数都最简、分母为正、零写作 `0/1`；每步都用规范化结果继续，不许把未约分对
   带进下一步。
3. 膨胀控制：各链的规范化位数峰值都 ≤ 64（预算），报告里的 peak、raw_peak 与结论要与引擎输出一致；
   离预算最近的是 `03_coprime`（peak=56）。
4. 规模与耗时：`06_scale` 是 12000 步，它的 `run` 单次墙钟 ≤ 10 秒（`time.perf_counter`，不含解释器启动）、
   峰值内存（`tracemalloc` 扣基线）≤ 128 MiB；`report` 全量 ≤ 30 秒。
5. 确定性：同一命令连跑两遍、`PYTHONHASHSEED=0/1/2` 下 stdout 与 HTML 逐字节相同；不写时间戳、随机数、
   绝对路径、进程号。
6. 退出码：0 成功；1 报告有不符；2 用法或输入错误（stderr 一行 `error: …`）。除 `var/` 与指定输出外
   不改动任何文件。
